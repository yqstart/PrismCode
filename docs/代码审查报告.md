## 一、严重问题（建议优先修复）

### S1. Markdown 预览链接过滤可被 HTML 实体混淆绕过（XSS）

- **位置**：`src/features/editor/markdown/preview.ts:65-71`（`isUnsafeProtocol`）、`:36-46`（`link` renderer）
- **实测复现**：`[x](java&#x73;cript:alert(1))` 与 `[x](jav&#x61;script:alert(1))` 均输出
  `<a href="java&#x73;cript:alert(1)">` —— `isUnsafeProtocol` 检查的是未解码的原始 href，
  不匹配 `javascript:` 正则；浏览器解析 href 属性时解码实体 → 点击后执行脚本。
  明文 `javascript:` / `vbscript:` / `data:text/html` 均已被正确拦截，raw HTML 已正确转义，
  **唯独实体混淆变体穿透**。
- **影响**：恶意 `.md` 文件预览时诱导点击链接 → 脚本在 WebView 应用上下文执行，
  可访问 Tauri IPC、localStorage。
- **修复**：`isUnsafeProtocol` 判定前先做 HTML 实体解码（`&#xNN;` / `&#NN;` / 命名实体），
  或对 href 采用白名单（http/https/mailto/相对路径/锚点）。

### S2. 更新说明弹窗裸用 marked 渲染远程内容（XSS 面，防线依赖隐式全局副作用）

- **位置**：`src/shared/UpdateNotesDialog.vue:19-25`（裸 `marked.parse` → L91 `v-html`）；
  数据源 `src/shared/changelog.ts:84-86` 从 `raw.githubusercontent.com` **网络拉取**
  CHANGELOG.md。
- **问题**：remote 内容渲染前无消毒。当前之所以未爆发，仅因 `preview.ts` 的全局
  `marked.use({ renderer: { html: 转义, link: 过滤 } })` 恰好随主包加载生效——
  防线依赖**模块加载顺序的隐式副作用**，任何一次改造成动态 import 即失效；
  且 S1 的实体混淆绕过对该路径同样成立。
- **修复**：显式复用 `renderMarkdown()`（preview.ts 的安全封装）而非裸 `marked.parse`，
  并同步修复 S1。

### S3. 编辑器会话快照上限远超 localStorage 配额，超限整套会话静默丢失

- **位置**：`src/shared/editorSession.ts:13-15`（`MAX_DIRTY_TABS=12`、`MAX_CONTENT_CHARS=1_000_000`）、
  `:141-165`（12 个 dirty tab × content+original 全量写入）、`:174-176`（catch 静默吞掉）
- **问题**：最坏 12 tab × 2M 字符 ≈ 48MB，而 localStorage 配额约 5MB。多文件（各几百 KB）
  未保存时 `QuotaExceededError` → **整个 key**（含所有干净标签的路径/光标/固定状态）写失败、
  静默丢弃 → 崩溃后热恢复整体失效、未保存内容丢失。
- **修复**：按预算分配（估算体积，超限先丢快照只留路径、再逐 tab 淘汰）；
  或迁移 IndexedDB；至少失败时 `console.warn`。

### S4. workspaceSymbols 工作区切换后不失效 → 跨工作区符号污染

- **位置**：`src/features/editor/workspaceSymbols.ts:76`（`workspaceScanned`）、`:79-84`（`clear()`）、
  `:120-124`（`searchSymbols` 无 root 校验）；`src/stores/workspace.ts` 切换 root 时无 `clear()` 调用
  （grep 证实 `clear()`/`invalidateAll()` 全库零调用点）
- **问题**：切换工作区后 `workspaceScanned` 仍 true、`globalIndex` 保留旧项目符号：
  新项目补全出现旧项目符号（绝对路径指向已不存在文件），且新工作区**永远不触发**
  `scanWorkspace`，跨文件符号功能在新项目里完全失效。另有 `getFileSymbols` 合并进
  `globalIndex` 不查重 + LRU 淘汰不清理 `globalIndex` → 无界增长。
- **修复**：workspace root 切换处调用 `workspaceSymbols.clear()`；LRU 淘汰时同步移除
  `globalIndex` 对应 path；合并前按 path 查重。

### S5. Git Log 日志加载被 refresh 序号系统性作废（确定性竞态）

- **位置**：`src/stores/git.ts:203`（`refresh` 内 `++refreshSeq`）、`:724-727`（`loadLog` 只捕获
  不自增，返回时 `seq !== refreshSeq` 即丢弃）；`src/features/git/GitLogPanel.vue:370`
  （`Promise.all([git.loadLog(120), git.refresh()])`）
- **实测推演**：`loadLog` 先同步捕获 seq=N 挂起；`refresh` 随后同步 `++refreshSeq` 变 N+1。
  `gitLog` IPC 返回时 `N !== N+1` **恒成立** → `log.value = result` 永不执行。
  面板内刷新按钮 / mod+R / fetch / pull 后日志不更新，停留在旧数据
  （仅当另一 refresh 恰好 in-flight 走 `refreshAgain` 合并分支时才侥幸成功）。
- **修复**：给 `loadLog` 独立自增序号，与 `refreshSeq` 解耦；
  或 `ensureLog` 改顺序 `await git.refresh(); await git.loadLog()`。

### S6. gitGraph 父车道索引陈旧，merge 拓扑连接线错位

- **位置**：`src/features/git/gitGraph.ts:54-67`（插入时记录 `next.indexOf(parent)`）、
  `:91-94`（画线用陈旧索引）
- **问题**：`parentLanes` 记录插入瞬间索引，但后续 `next.splice(insertAt, 0, parent)` 会把
  已在车道等待的父提交挤到右侧、索引不更新。最普通的 merge（parents=[主线 X, 分支 Y]）即触发：
  X 被 Y 挤到 lane1 但连接线画在 lane0，线错位/断裂、lane0 底部多出重叠线。
- **修复**：`parentLanes` 改存父提交 id，生成 connectors 时用 `deduped.indexOf(parent)` 取最终车道。

### S7. lineDiff Myers 回溯内存 O(D×(N+M))，大文件编辑冻结主线程

- **位置**：`src/features/editor/lineDiff.ts:31-37`（每轮 `trace.push(v.slice())` 复制整条
  `Int32Array(2*max+1)`）；`src/features/editor/gitChanges.ts:166-174`（docChanged 250ms 防抖后
  无条件全量 `recompute`，无行数护栏）
- **问题**：新建大文件（`gitHeadText` 为空）或大段替换时 D≈N+M，5000 行差异 trace 临时分配
  ~200MB、主线程同步执行 → 2000+ 行文件大块粘贴/替换可冻结 UI 数秒甚至 OOM。
- **修复**：超过阈值（如 2000 行）降级为文件级 dirty 标记/逐块对比；
  或改线性空间回溯（存极值、回溯重跑）；差异结果按文档版本缓存。

### S8. TypeScript 语言服务程序无界增长 + 每次按键级查询重扫 import 闭包

- **位置**：`src/features/editor/typeService/tsService.ts:152-153`（`fileContents`/`scriptNames`
  只增不减）、`:227-233`（`removeFile` 全库零调用点）、`typeService/index.ts:81-127`
  （`ensureTypeScriptProgram` 每次调用遍历全部 tabs setFile + 正则 BFS 展开 import 闭包，
  `visited` 局部、无跨调用缓存）
- **问题**：① 标签关闭后文件残留，长期会话 TS 程序持续膨胀（仅切换工作区时清空）；
  ② 补全（每键）、诊断、hover、签名、定义/引用全部走 `ensureTypeScriptProgram`，
  import 闭包扫描与磁盘读每键重复执行。
- **修复**：标签关闭时调 `removeFile`；「文件 → import 闭包」按内容 hash 缓存；
  tabs 增量同步（仅脏文件 setFile）。

### S9. window_chrome 在 tokio worker 线程执行 AppKit 调用（违反主线程约定）

- **位置**：`src-tauri/src/commands/window_chrome.rs:49-67`（`set_titlebar_background` /
  `sync_traffic_lights` 同步 command），实际 AppKit 调用 `:39-44`（`class_replaceMethod`）、
  `:98-99`（`setBackgroundColor`）、`:156-188`（`setFrame`/`setFrameOrigin`/`superview` 链）
- **依据**：Tauri 2 所有 command（含同步）均 spawn 到 tokio 异步运行时（已读
  tauri-macros `wrapper.rs:378` 与 `ipc/mod.rs:354` 源码验证）。本项目 `lib.rs:187`
  dock_menu 已正确示范 `run_on_main_thread`，window_chrome 属同类遗漏。
  NSView/NSWindow UI 方法 + swizzle 在非主线程调用存在崩溃/竞态/布局异常风险。
- **修复**：两命令改 async + `run_on_main_thread` 转发（仿 dock_menu）。

### S10. security_scoped 的 thread_local URL 表跨线程不配对（NSURL + TCC 授权泄漏）

- **位置**：`src-tauri/src/commands/security_scoped.rs:157-159`（resolve 时 push 到
  `ACTIVE_URLS` thread_local）、`:180-182`（`thread_local!` 声明）、`:165-177`（`release_all`
  只读当前线程的 Vec）
- **问题**：resolve 与 release 是同步 command，跑在 tokio 线程池，两次 invoke 不保证同一线程。
  release 落在其他线程时表为空 → 不调 `stopAccessingSecurityScopedResource()`、不 release
  retain 过的 NSURL：每次会话恢复泄漏一个 NSURL + 一个 TCC 授权计数。
- **修复**：改进程级 `Mutex<Vec<usize>>`，或统一 `run_on_main_thread`。

### S11. replace_in_files 无文件大小上限（大文件整读内存暴涨 + 超时后后台继续写）

- **位置**：`src-tauri/src/commands/search.rs:359-367`（`fs::read` 无大小检查）、`:331`
  （120s 超时无法取消 spawn_blocking 线程）
- **问题**：同文件 `search_content` 有 2MB 上限、fs.rs 文本读 20MB / base64 40MB，唯独
  全工作区替换对每个文件无条件整读；几百 MB 文件直接读入内存；超时后旧任务仍在后台覆写文件。
- **修复**：读前 metadata 加字节上限（对齐 2MB），超限跳过并计入报告。

### S12. 终端脚本名注入：package.json 键名无转义拼入 shell 命令（任意命令执行）

- **位置**：`src/shared/packageScripts.ts:37-48`（`formatRunCommand` 直接
  `pnpm run ${scriptName}` 拼接）、`:62-64`（`loadPackageScripts` 只过滤空名/非字符串，
  不校验键名字符）
- **问题**：脚本名来自项目 package.json 的 scripts 键，随后经 `runInLocalTerminal` 送入
  本地 PTY 由 shell 直接执行。恶意键名 `"x; echo INJECTED > /tmp/pwn"` 拼成
  `pnpm run x; echo INJECTED > /tmp/pwn` → shell 拆成两条命令。打开恶意项目 +
  点击一次脚本芯片即本地任意命令执行；含空格/`&`/`|`/`$()`/反引号的键名同样破坏语义。
  （SSH 路径走 ssh2 结构化传参，无此问题，已核实。）
- **修复**：`formatRunCommand` 对键名做 shell 单引号转义（`'` → `'\''`），
  或白名单校验 `/^[A-Za-z0-9._:/-]+$/`，非法键名拒绝执行并提示。

- **M35** `ssh.rs:665-676` `ssh_shell_write` 持 channel 锁做最多 100×10ms 重试，期间读线程阻塞。
- **M36** `search.rs:290-299` 大小写不敏感搜索的列号取 lowercased 文本字节偏移，

### 终端 / SSH（src/features/sessions + stores/sessions + stores/ssh）

- **M40** `terminalIdle.ts:17,39-47` 行尾特征误判忙→闲：输出行尾恰为 `$ % # > ❯ »`
  的长任务（进度条 `42%`、`top` 统计行、无换行日志尾）被判定为空闲 → 点击脚本芯片时
  `runInLocalTerminal` 复用 busy 终端，命令注入运行中的任务（发进其 stdin 或丢失）。
  收紧匹配特征（`%` 降级、要求提示符上下文），现有 13 条自测用例未覆盖这些形态。
- **M41** `LocalTerminal.vue:127-129` shell 退出后终端僵尸化：`onExit` 只打一行
  「进程已退出」，不置空 pty、不上报 idle → 后续芯片点击判「非 busy」复用僵尸终端，
  `pty.write` 落到已死会话（tauri-pty 内部 console.error 吞错）→ **命令静默丢失无任何反馈**。
  onExit 中重置 pty/idle，pendingLocalWrite 等待循环把「pty 已退出」视为失败并提示。
- **M42** `RemoteTerminal.vue:68-78` `fit()` 无宿主可见性守卫（LocalTerminal 有）：
  SSH 标签隐藏保活时窗口 resize → 0 尺寸容器 fit → 远端 PTY 缩到 ~2 列，隐藏期间
  vim/less 持续错误尺寸渲染。
- **M43** `ssh.rs:518-524` `ssh_shell_open` 90s timeout 不取消 spawn_blocking 连接任务：
  超时后 DNS+TCP 尝试继续后台运行（最多再拖 ~90s），用户重试同主机产生重复并发连接。
  加取消标志（`Arc<AtomicBool>`）在连接步骤间检查。
- **M44** `ssh.rs:665-677` `ssh_shell_write` 同步命令持 channel 锁忙等（100×10ms），
  阻塞读线程 → 慢网络下远端输出延迟；与 Rust M35 同源。改 async + spawn_blocking。
- **M45** `terminalIdle.ts:80` 残余 buffer 无界：无换行超长输出（cat 无换行文件/二进制流）
  使 buffer 无限累加 + 每 chunk 全量 stripAnsi 正则，O(n²) 开销。超 64KB 截断（超长
  残余不可能命中 ≤300 字符的提示符判定，截断不影响正确性）。
- **M46** `SshHostsView.vue:148-167` 编辑主机时清空密码输入框无法清除已存密码
  （`pwd || existing?.password` 兜底），只能取消勾选「记住密码」。改「空串 = 显式清除」语义。
- **M47** `ssh.ts:168-180` `resetForWorkspace` 不重置 open/focused/dormant：切换项目前
  SSH 聚焦时，切后画布仍被主机列表抢占，与本地终端侧行为不一致。
- **M48** `sessions.ts:314-325` + `LocalTerminal.vue:236-264` `pendingLocalWrite` 快速连续
  注入时消费依赖 watcher 注册次序（seq 不匹配即跳过，靠顺序兜底），脆弱；

## 四、值得肯定的设计（抽查确认）

- **路径安全防线系统**（Rust）：`ensure_inside_workspace` 拒绝 `..` 组件 + canonicalize 前缀比较 +
  不存在路径向上找祖先再比较，symlink 逃逸有防护；fs 命令全部接入
- **凭据处理**：SSH 凭据 0600、known_hosts TOFU 锁内读-改-写、临时凭据 percent-encode
- **异步竞态防护体系**：workspace `workspaceEpoch`、git `refreshSeq`/`refreshAgain` 合并、
  search 请求序号、editor `openAtSeq`/`referencesRequestSeq`、QuickOpen 150ms 防抖——各 store 成体系
- **资源生命周期**：各组件监听/定时器/编辑器实例 onUnmounted 清理齐全，无 setInterval 滥用，
  PTY 保活与销毁时机处理细致（含「隐藏态挂载补启动 + 重新 fit」的边界）
- **性能意识**：阻塞 IO 全面 spawn_blocking + 超时；documentSymbols 双键缓存、
  semanticScanner djb2 记忆化、终端输出有界队列；perf bench 热路径 0.2-0.5µs
- **测试基建**：8+ 套 node 直测脚本 + Rust 集成测试（含真实 git、并发、凭据转义场景），全部通过
