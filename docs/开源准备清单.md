# 开源准备清单

本文档记录「源码侧已就绪」与「需在 GitHub / 发布侧人工完成」的事项，便于公开发布时逐项勾选。

## 源码侧（仓库内）

- [x] MIT `LICENSE`（版权行：`Copyright (c) 2026 PrismCode`）
- [x] `THIRD-PARTY-NOTICES.md`（含 libgit2 linking exception、Material Icon Theme 等）
- [x] `README.md`（快速开始、环境、功能、文档索引、品牌说明）
- [x] `CONTRIBUTING.md` / `SECURITY.md` / `CODE_OF_CONDUCT.md`
- [x] `CHANGELOG.md`（发版前将 `[Unreleased]` 归入版本节）
- [x] Issue / PR 模板（`.github/`）
- [x] CI：前端 `pnpm build` + Rust `cargo check`（`.github/workflows/ci.yml`）
- [x] `.gitignore` 忽略 `.env`；样例使用 `.env.example`
- [x] 敏感信息抽查：无私钥 / 证书 / 硬编码密钥（示例 `.env` 仅为占位）

## GitHub 仓库设置（人工）

- [ ] Settings → **Change visibility → Public**（若尚未公开）
- [ ] About：描述、Topics（建议：`tauri`、`vue`、`codemirror`、`editor`、`desktop`）
- [ ] Settings → Code security → 开启 **Secret scanning** / **Dependabot alerts**（公开后可用）
- [ ] Settings → Code security → **Private vulnerability reporting**（与 `SECURITY.md` 对齐）
- [ ] 确认默认分支保护（可选：Require PR）

## 发版（当前基线：v1.0.0）

> 发版前确认 `package.json` / `tauri.conf.json` / `Cargo.toml` 三处版本号一致，并将 `CHANGELOG.md` 的 `[Unreleased]` 归入新版本节。流程见 [docs/多平台发布.md](多平台发布.md)。

- [x] 多平台发版工作流：`.github/workflows/release.yml`
- [x] 用法说明：`docs/多平台发布.md`
- [x] updater 签名密钥：仓库 Secrets `TAURI_SIGNING_PRIVATE_KEY`（见多平台发布文档）
- [ ] 提交并推送文档与版本号变更到 `master`
- [ ] 打标签并推送：`git tag vX.Y.Z && git push origin vX.Y.Z`
- [ ] Settings -> Actions -> Workflow permissions -> **Read and write**
- [ ] Actions -> Release 全绿；Releases 页有各平台 Assets 与 `latest.json`
- [ ] macOS：Developer ID 签名 + 公证（Secrets，可后置）
- [ ] Windows：代码签名（可后置）

- 长期可自行检索商标冲突风险；必要时调整对外宣传口径

```bash

pnpm build

# Rust 编译检查
cargo check --manifest-path src-tauri/Cargo.toml

# 可选：本地密钥扫描（需自行安装 gitleaks）
```
